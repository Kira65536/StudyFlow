# StudyFlow Bot

StudyFlow — учебный backend-проект на Python для управления задачами и планирования учебной или рабочей нагрузки через REST API и Telegram-бота. Проект использует локальную AI-модель для генерации планов и перепланирования незавершённых задач.

**Статус:** проект запускается локально. Публичный сервер для постоянной работы пока не развёрнут. Репозиторий предназначен для изучения кода, запуска проекта на собственном компьютере и демонстрации backend-навыков.

## Возможности

- Регистрация и авторизация пользователей.
- JWT-аутентификация.
- CRUD-операции с задачами: создание, просмотр, редактирование и удаление.
- Управление статусами, приоритетами и дедлайнами.
- Telegram-бот на Aiogram для работы с задачами.
- Привязка Telegram-аккаунта к пользователю StudyFlow.
- Генерация учебных планов с помощью AI.
- Предварительный просмотр и сохранение сгенерированных задач в PostgreSQL.
- Перепланирование незавершённых задач.
- Локальная интеграция с Ollama.
- Миграции базы данных через Alembic.
- Автоматические тесты с Pytest.

## Запуск проекта через Docker Compose

### Требования

Перед началом установите:

- Git;
- Docker Engine и Docker Compose;
- Telegram-аккаунт для создания собственного бота;
- Ollama и модель `qwen2.5:3b` для локальных AI-функций.

Команды ниже предназначены для Linux или WSL. На других системах способ установки Docker и Ollama может отличаться.

### 1. Клонирование репозитория

```bash
git clone https://github.com/Kira65536/StudyFlow.git
cd StudyFlow
```

### 2. Настройка Telegram-бота и переменных окружения

Создайте собственного Telegram-бота через [@BotFather](https://t.me/BotFather) и получите токен.

Создайте локальный файл `.env` на основе шаблона:

```bash
cp .env.example .env
```

Откройте `.env` и заполните необходимые значения:

```env
DATABASE_URL=
JWT_SECRET=replace-with-a-long-random-secret
TELEGRAM_BOT_TOKEN=your-own-telegram-bot-token
```

- `DATABASE_URL` — строка подключения к базе данных. При запуске через Docker Compose подключения API и бота могут задаваться в `docker-compose.yml`.
- `JWT_SECRET` — секретный ключ для подписи JWT-токенов. Используйте случайное значение достаточной длины.
- `TELEGRAM_BOT_TOKEN` — токен собственного Telegram-бота.

Не используйте чужой токен и не публикуйте файл `.env`, пароли или секретные ключи.

### 3. Установка и запуск Ollama

Установите Ollama, следуя инструкциям на [официальном сайте](https://ollama.com/).

Загрузите модель:

```bash
ollama pull qwen2.5:3b
```

Проверьте, что модель доступна:

```bash
ollama list
```

**Важно:** если Ollama работает на хост-машине, а API запускается в Docker, адрес `127.0.0.1` внутри контейнера указывает на сам контейнер, а не на хост. Поэтому необходимо настроить доступ к Ollama с учётом операционной системы и сетевой конфигурации Docker.

Не открывайте порт Ollama для недоверенных сетей. Для доступа из контейнера используйте подходящий адрес хоста и ограничивайте сетевой доступ.

### 4. Запуск приложения

Из корня проекта выполните:

```bash
docker compose up -d --build
```

При запуске API применяет миграции Alembic и затем запускает Uvicorn. PostgreSQL запускается в отдельном контейнере.

Проверьте состояние контейнеров:

```bash
docker compose ps
```

Посмотрите логи:

```bash
docker compose logs --tail=100 api
docker compose logs --tail=100 bot
docker compose logs --tail=100 db
```

Если контейнеры запустились, но AI-функции не работают, проверьте доступность Ollama из API-контейнера и адрес, указанный в `services/ai_service.py`.

### 5. Проверка API

Swagger UI:

http://localhost:8000/docs

Проверка состояния API:

http://localhost:8000/health

PostgreSQL публикуется на порту `15432` хост-машины. Внутри Docker API подключается к сервису `db` на порту `5432`.

### 6. Проверка Telegram-бота

Откройте Telegram-бота, токен которого указан в `.env`, и отправьте команду `/start`.

Если бот не запускается, проверьте токен и логи:

```bash
docker compose logs --tail=100 bot
```

В некоторых сетях для подключения к Telegram может потребоваться прокси. Настройка зависит от вашей среды и конфигурации приложения.

### 7. Остановка проекта

```bash
docker compose down
```

Данные PostgreSQL сохраняются в Docker volume `postgres_data`.

Команда ниже удаляет также сохранённые данные базы, поэтому используйте её только при необходимости:

```bash
docker compose down -v
```

## AI-функции

### Генерация плана

Пользователь задаёт цель и параметры плана. AI формирует список задач, который можно предварительно просмотреть и сохранить в PostgreSQL.

### Перепланирование

StudyFlow может сформировать новый порядок выполнения незавершённых задач и скорректировать план с учётом оставшейся работы.

### Ollama

В проекте используется локальная модель `qwen2.5:3b`. Для её работы необходим установленный Ollama и доступность модели из среды, где запущен API.

## Тестирование

Для локального запуска тестов установите зависимости проекта в виртуальное окружение, если они ещё не установлены:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Запустите тесты:

```bash
pytest -v
```

Последняя зафиксированная проверка проекта: **31 тест пройден**. Результат может зависеть от текущего состояния кода и окружения.

## Безопасность

- Секреты должны храниться в локальном `.env`, который не публикуется в Git.
- Для примера переменных окружения используется `.env.example`.
- Не публикуйте токены Telegram, пароли базы данных и секреты JWT.
- Пароли пользователей должны храниться в виде хешей.
- Не предоставляйте публичный доступ к Ollama без необходимости и соответствующих ограничений.
