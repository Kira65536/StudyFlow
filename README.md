# StudyFlow Bot

**StudyFlow** — учебный backend-проект на Python для управления задачами и планирования учебной или рабочей нагрузки через REST API и Telegram-бота. Проект использует локальную AI-модель для генерации планов и перепланирования незавершённых задач.

## Возможности

- Регистрация и авторизация пользователей.
- JWT-аутентификация.
- CRUD-операции с задачами: создание, просмотр, редактирование и удаление.
- Управление статусами, приоритетами и дедлайнами.
- Telegram-бот на Aiogram для работы с задачами.
- Привязка Telegram-аккаунта к пользователю StudyFlow.
- Генерация плана задач с помощью AI.
- Предварительный просмотр и сохранение сгенерированных задач в PostgreSQL.
- Перепланирование незавершённых задач.
- Локальная интеграция с Ollama.
- Миграции базы данных через Alembic.
- Автоматические тесты с Pytest.

## Запуск через Docker Compose

### Требования

- Git
- Docker
- Docker Compose
- Telegram-бот и токен, полученный через BotFather
- Ollama и совместимая модель — для использования AI-функций

### 1. Клонирование репозитория

```bash
git clone https://github.com/Kira65536/StudyFlow.git
cd StudyFlow
```

### 2. Настройка переменных окружения

Создайте `.env` на основе шаблона:

```bash
cp .env.example .env
```

Заполните `.env`:

```env
DATABASE_URL=
JWT_SECRET=your-secret-key
TELEGRAM_BOT_TOKEN=your-telegram-bot-token
```

- `DATABASE_URL` — в Docker Compose подключения к базе данных API и бота задаются в `docker-compose.yml`.
- `JWT_SECRET` — секретный ключ для подписи JWT-токенов. Используйте случайное значение достаточной длины.
- `TELEGRAM_BOT_TOKEN` — токен Telegram-бота.

Не публикуйте настоящий `.env`, токены, пароли или секретные ключи.

### 3. Запуск проекта

```bash
docker compose up -d --build
```

При запуске API применяет миграции Alembic, затем запускает Uvicorn. PostgreSQL запускается в отдельном контейнере.

Проверить состояние сервисов:

```bash
docker compose ps
```

Посмотреть логи:

```bash
docker compose logs --tail=100 api
docker compose logs --tail=100 bot
docker compose logs --tail=100 db
```

### 4. Проверка API

Swagger UI:

http://localhost:8000/docs

Проверка состояния API:

http://localhost:8000/health

PostgreSQL публикуется на порту `15432` хост-машины. Внутри Docker API подключается к сервису `db` на порту `5432`.

### 5. Работа с Telegram-ботом

Откройте своего Telegram-бота и отправьте команду `/start`.

Для запуска бота требуется действительный токен Telegram. Если подключение к Telegram требует прокси, настройте соответствующую переменную окружения и сетевое подключение в соответствии со своей средой.

### 6. Остановка проекта

```bash
docker compose down
```

Данные PostgreSQL сохраняются в Docker volume `postgres_data`. Чтобы удалить также данные базы, используется команда `docker compose down -v`. **Она удаляет сохранённые данные — применяйте её только при необходимости.**

## AI-функции

### Генерация плана

Пользователь задаёт цель, количество задач и продолжительность плана. AI формирует структурированный список задач с названиями, описаниями, приоритетами и дедлайнами. После предварительного просмотра задачи можно сохранить в PostgreSQL.

### Перепланирование

StudyFlow может сформировать новый порядок выполнения незавершённых задач, скорректировать приоритеты и назначить новые дедлайны. Существующие задачи не должны создаваться или удаляться в процессе перепланирования.

### Ollama

Для локальной работы AI установите Ollama и загрузите модель, например:

```bash
ollama pull qwen2.5:3b
```

При запуске Ollama отдельно от Docker убедитесь, что контейнеры могут обращаться к сервису Ollama по доступному адресу. Конкретный адрес зависит от конфигурации среды.

## Тестирование

Запуск тестов:

```bash
pytest -v
```

Последняя проверка проекта: **31 тест пройден**.

Тесты охватывают системные эндпоинты, авторизацию, операции с задачами, AI-функции и элементы взаимодействия Telegram-бота.

## Безопасность

- Секреты хранятся в локальном `.env`, который не должен попадать в Git.
- Для примера переменных окружения используется `.env.example`.
- Пароли пользователей должны храниться в виде хешей.
- JWT подписываются секретным ключом из конфигурации приложения.
